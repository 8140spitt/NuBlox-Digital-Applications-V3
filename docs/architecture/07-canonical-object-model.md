# 07 — Canonical Object Model

NuBlox operates through one canonical enterprise object graph.

## Initial canonical families

### Parties and organisation
Party, Person, Organisation, Organisation Unit, Position, Team, Membership.

### Commercial and relationship
Customer, Supplier, Contract, Agreement, Obligation.

### Delivery context
Portfolio, Programme, Project, Work Package, Site, Facility, Space, System, Asset.

### Product and configuration
Item, Product, Requirement, Configuration, Baseline, Effectivity.

### Information
Information Container, Document, Record, Representation, Classification.

### Governance and execution
Function, Process, Activity, Task Definition, Job Profile, Competence, Deployment, Assignment, Work Item, Deliverable Requirement, Deliverable Item.

### Control
Workflow, Lifecycle, Change, Decision, Approval, Issue, Acceptance, Event, Evidence, Audit Entry.

## Relationship principle

Relationships are first-class governed objects where relationship identity, role, validity, authority, effectivity or evidence matters.

## Identity principle

Enterprise identity must survive changes of state, representation, organisational ownership and system integration. Versioned objects distinguish stable identity from revision and working iteration where the object type requires configuration control.
