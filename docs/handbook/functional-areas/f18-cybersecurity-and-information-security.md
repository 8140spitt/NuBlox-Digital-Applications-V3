# F18 — Cybersecurity & Information Security

## Why this functional area exists

Protect the confidentiality, integrity and availability of the organisation's information, technology and digital operations.

NuBlox must allow the people responsible for this function to carry out the complete function without relying on disconnected departmental spreadsheets or applications for its core enterprise work.

## What the function is responsible for

- define security strategy, policies and control framework;
- design security architecture and control patterns;
- govern identity/access security and privileged access;
- identify and remediate vulnerabilities;
- manage patch security assurance;
- operate security monitoring/SOC and detection;
- respond to cyber incidents;
- collect and assess threat intelligence;
- perform penetration and security testing;
- embed application security;
- assess third-party security risk;
- deliver security awareness;
- manage cryptography/PKI;
- monitor security compliance;

## Typical people who work in this function

- CISO / Security Director;
- Security Architect;
- IAM Security Engineer;
- SOC Analyst;
- Cyber Incident Responder;
- Vulnerability Manager;
- Penetration Tester;
- Application Security Engineer;
- Third-Party Security Risk Specialist;
- Security Compliance Manager;
- PKI / Cryptography Specialist;

Job titles vary by organisation. The functional area describes the business responsibility; Job Profiles and Positions describe who performs it.

## What people do day to day

- monitor alerts/logs;
- investigate anomalies;
- triage/remediate vulnerabilities;
- review privileged/access controls;
- respond to cyber incidents;
- perform threat/security assessments;
- test systems/applications;
- monitor supplier security;
- manage keys/certificates;
- collect compliance evidence;

## Core information and data

- assets/systems;
- security controls;
- identities/access;
- vulnerabilities;
- patches;
- events/alerts;
- incidents;
- threat indicators;
- test findings;
- third parties;
- security training;
- cryptographic keys/certificates;

The function consumes shared enterprise data and contributes new governed business state. It must not create private copies of canonical customers, suppliers, projects, people, contracts, assets or other shared objects.

## Key transactions, records and outputs

- security strategy/policy;
- security architecture review;
- access certification;
- vulnerability finding;
- patch test/deployment evidence;
- security alert/investigation;
- cyber incident;
- threat advisory;
- penetration-test report;
- third-party assessment;
- awareness result;
- key/certificate lifecycle record;
- compliance evidence pack;

These may be structured records, calculations, controlled information, transactions, decisions, inspections, reports or handover packages. NuBlox must support the appropriate form rather than forcing every output into a document.

## Decisions and controls

- security exception;
- risk acceptance;
- privileged/access certification;
- incident severity/response;
- vulnerability priority;
- security release acceptance;
- third-party remediation/acceptance;
- certificate/key revocation;

Authority must be enforced independently from job title. Assignment to work does not itself grant approval, financial, contractual or access authority.

## Performance measures

Typical measures include:

- critical vulnerabilities;
- time to remediate;
- incident MTTD/MTTR;
- phishing/training performance;
- access-review completion;
- patch compliance;
- third-party risk;
- security-control compliance;
- certificate/key expiry exposure;

Measures are configurable by tenant and should drill back to the underlying governed data.

## How this function interacts with the rest of the business

- F16 IT for technology operations;
- F17 Data for data access/AI;
- F20 Risk/Compliance for enterprise controls;
- F21 Privacy for breach response;
- F24 Crisis/Continuity for major incidents;
- all functions as security consumers;

The handoffs use shared canonical objects and governed workflows rather than point-to-point copies between departmental systems.

## What NuBlox must provide

For this functional area to be genuinely operable inside NuBlox, the product must provide:

- security control/policy library;
- security architecture reviews;
- common identity/access authority integration;
- vulnerability/finding/remediation workflow;
- SOC alert and cyber incident cases;
- threat intelligence;
- security testing evidence;
- supplier security assessments;
- awareness tracking;
- key/certificate lifecycle;
- security compliance dashboards;

## Product-completeness test

This function is not complete because a menu item or dashboard exists.

It is complete when authorised people in this functional area can execute their normal end-to-end responsibilities in NuBlox, including the exceptions, approvals, evidence, handoffs and reporting required by a sophisticated construction and built-environment business.
