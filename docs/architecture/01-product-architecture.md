# 01 — NuBlox Product Architecture

## Product definition

NuBlox is a configurable **enterprise operating platform**, not a collection of disconnected functional applications.

It must support three inseparable concerns:

1. **How the organisation operates** — governance, functions, processes, people, authority, finance, risk, data and corporate services.
2. **How the organisation delivers value** — programmes, projects, contracts, products, services, work packages, sites, assets and operational delivery.
3. **What the organisation actually produces** — controlled business objects, technical information, physical outcomes, deliverables, decisions, evidence and records.

## Product layers

### Enterprise Kernel

The kernel owns shared identities, relationships and control mechanisms used by every functional domain and industry solution.

### Functional Domains

The 29 enterprise functions are governed capability definitions. Each function receives native tools and operating experiences while remaining part of one canonical enterprise object graph.

### Native Work-Delivery Runtime

The work runtime converts governed capability into actual assignments, tasks, deliverables, decisions, approvals, issues, acceptances and evidence.

### Industry Solutions

Industry solutions configure the kernel and functional platform for a sector without forking the product. The first solution is **NuBlox Construction & Built Environment**.

## Architectural objective

A user should experience NuBlox as one enterprise system whose behaviour is shaped by their organisation, position, job profile, deployment, authority, operating context and work obligations—not as a menu of unrelated modules.
