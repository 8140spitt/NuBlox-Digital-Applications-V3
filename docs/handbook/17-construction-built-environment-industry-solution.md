# 17 — Construction & Built Environment Industry Solution

**Status:** Governing industry-solution architecture  
**Effective:** 20 September 2026

## Purpose

NuBlox Construction & Built Environment is the first Industry Solution configured on the NuBlox Enterprise Operating Platform.

It is not the whole NuBlox product.

It applies the shared Enterprise Kernel, 29 governed enterprise functions and Native Work-Delivery Runtime to the Construction & Built Environment sector.

## Industry-solution composition

The solution combines:

- the 29 enterprise functions;
- 16 Construction & Built Environment delivery domains;
- 84 governed Job Profiles;
- sector-specific project, contract, package, site, system and asset context;
- sector-specific Deliverable Requirements and Deliverable Items;
- construction-specific competence, assurance and regulatory requirements;
- delivery lifecycle from market/client through operation and maintenance.

## The 16 delivery domains

The 16 delivery domains are professional/trade composition structures for the Construction & Built Environment solution.

They group the 84 sector Job Profiles into recognisable delivery capability areas.

They are not:

- separate applications;
- separate databases;
- access-control boundaries;
- substitutes for the 29 enterprise functions.

They help configure:

- Job Profile capability;
- terminology;
- likely process participation;
- competence requirements;
- workspace relevance;
- typical tools;
- typical work products;
- deployment context.

## The 84 Job Profiles

The 84-job catalogue is a governed industry capability catalogue.

A Job Profile defines reusable expectations such as:

- purpose;
- responsibilities;
- capability;
- skills/competence;
- qualifications where applicable;
- process participation;
- typical deliverables/work products;
- tools;
- assurance responsibilities;
- authority expectations.

A Job Profile is not a Person.

A Person may be employed/engaged into a Position whose job expectation references a Job Profile.

That Person may then be deployed differently across Projects, Contracts, Packages, Sites or Assets.

## Functional and delivery-domain intersection

Enterprise Functions and Construction Delivery Domains are complementary.

Examples:

- Architecture & Design work intersects Project Management, Quality, HSE, Information Management, Commercial and other functions.
- Commercial / Contracts / Cost work intersects Finance, Legal, Procurement, Project Management and Governance.
- Building Trades work intersects Project Management, HSE, Quality, Materials, Plant/Resource and Commercial controls.
- Asset Operations work intersects Asset Management, Facilities, Finance, Procurement, HSE, Quality and Service Management.

No Job Profile should be forced into one enterprise function merely to simplify ownership.

## Information-to-physical continuity

The Construction & Built Environment solution must preserve continuity across technical definition and physical delivery.

~~~text
Requirement
-> Deliverable Requirement
-> Deliverable Item
-> Design / technical definition
-> Approved / released configuration
-> Procurement / fabrication / construction work
-> Delivered material / product
-> Installed component / system
-> Inspection / test / commissioning
-> As-built information
-> Handover
-> Operational Asset
-> Maintenance / change history
~~~

A drawing is not the installed asset.

A model is not the physical system.

An inspection record is not the installed work.

The objects are related, not conflated.

## Project and functional deployment

A sector worker must be deployable into specific work context.

Example:

~~~text
Architect Job Profile
-> Position
-> Person
-> Functional Deployment
-> Project Alpha
-> Design Package A
-> RIBA stages 3-5
-> Responsible Deliverables
-> competence / authority
-> assigned drawings/models/specifications
-> review/approval obligations
~~~

The same pattern applies to Quantity Surveyors, Engineers, Site Managers, Trades, BIM/Information professionals, Facilities Managers and the other Job Profiles.

## Industry-solution acceptance test

For each of the 84 Job Profiles NuBlox must be able to answer:

- What is this job expected to do?
- Which Functions and delivery domains does it participate in?
- What competence is required?
- Into which construction contexts can it be deployed?
- What native/connected tools does the job need?
- What work is assigned?
- What outputs does it produce?
- Which controls, reviews and Decisions apply?
- How does its work affect Project, Contract, cost, programme, quality, safety, configuration and Asset truth?
- What evidence proves the work was completed correctly?

The Construction & Built Environment solution is complete only when real people can perform the jobs they are employed and deployed to do through the NuBlox operating model.
