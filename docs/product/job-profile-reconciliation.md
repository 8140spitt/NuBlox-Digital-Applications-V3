**Status:** governing reconciliation gate established

## Executive decision

The 382 inherited candidate Job Profiles must **not** be treated as 382 finished employment jobs.

They were generated primarily from the 29-function / 353-sub-function architecture and are valuable source provenance, but many represent functional capability slices that a real employee performs as part of a broader job.

The reconciliation question for every inherited profile is:

> **Is this a real reusable employment Job Profile, one component of a broader employment Job Profile, or only Functional-Role provenance?**

Until that decision is made, the profile remains candidate architecture rather than an approved tenant Job Profile.

## Reconciliation states

| State | Meaning |
| --- | --- |
| `candidate-direct-employment-profile` | Wave evidence identifies a plausible direct employment-job base; validate rather than regenerate it. |
| `candidate-composition-source` | The source profile contributes Functional Roles to a broader cross-functional employment job. |
| `candidate-adjacent-source-only` | The source profile is useful adjacent provenance but does not represent the target employment job. |
| `candidate-unreconciled-source-profile` | No Wave 1-4 employment archetype currently establishes its treatment. |

None of these states grants permissions or creates Positions.

## Required decision for every source profile

Each of the 382 candidates must ultimately receive one treatment:

1. **RETAIN AS EMPLOYMENT JOB** — the profile describes an independently employable reusable job and survives as a governed Job Profile.
2. **COMPOSE INTO EMPLOYMENT JOB** — its Functional Roles/accountabilities are reused by one or more broader employment Job Profiles.
3. **FUNCTIONAL-ROLE PROVENANCE ONLY** — it remains a capability/accountability source but is not exposed as a standalone Job Profile.
4. **REPLACE / SUPERSEDE** — a professionally validated Job Profile supersedes the generated candidate.
5. **OUT OF SCOPE** — only with explicit product/market rationale.

## Non-negotiable separation

```text
Functional Role
  != Job Profile
  != Position
  != Person
  != Access Role
  != Permission
  != Delegated Authority
```

A reconciliation decision must never grant access.

## Completion contract

A profile can leave J1 only when:

- its employment treatment is decided;
- its contributing Functional Roles and exact source activities are known;
- material Work Products are explicit rather than generic;
- predecessor/input and downstream handoffs are known;
- Career/professional synonyms are mapped where relevant;
- duplicate/overlapping source-profile semantics are resolved;
- the result is traceable to the 29-function architecture without forcing the employment job into one function.

## Sequencing

The next work should reconcile the 382-source inventory by coherent job-family waves, starting with profiles already referenced by the 95 employment archetypes, then progressing across the remaining function-derived families.

J2 canonical/aggregate/lifecycle/authority mapping can proceed for validated high-priority Work Products, but J1 must not be declared complete until the 382-profile reconciliation register has no unresolved candidate profile.
