# NuBlox Market Tool & Job Capability Landscape

**Status:** Active benchmark discovery register  
**Effective:** 21 September 2026  
**Scope:** NuBlox Digital Applications V3 — 29 enterprise functions and Construction & Built Environment job/tool research

## Purpose

This register changes the benchmark question from **"which enterprise suite competes with NuBlox?"** to:

> **For each Function, Sub-function, Activity and Job Profile, what work does a real person perform, which market tools currently enable that work, what work products do those tools create, and what must NuBlox provide natively?**

The governing chain is:

```text
Function
-> Sub-function
-> Activity
-> Job Profile participation
-> Job task
-> Market tool / module
-> operation performed
-> work product / transaction / decision / evidence
-> canonical NuBlox object
-> lifecycle / workflow / authority / assurance
-> NuBlox native requirement
```

## Research rules

1. The 29 enterprise Functions remain the stable functional taxonomy.
2. Construction & Built Environment Job Profiles remain cross-functional; they are **not** forced into a single Function.
3. Market products are benchmark evidence, migration sources and interoperability references — not NuBlox runtime dependencies.
4. Product-suite names are insufficient. Research must descend to the **module, user operation and work-product** level.
5. Specialist professional authoring tools are first-class benchmark targets. ERP coverage alone does not prove that a person can perform their job.
6. A market product can map to multiple Functions, Job Profiles and work products.
7. This is a living discovery register. "All tools" means systematically expanding the market universe; no static list can prove every commercial or open-source product worldwide has been captured.

## What the machine-readable register must become

[market-tool-register.csv](market-tool-register.csv) is the discovery spine. It starts with market products mapped to the 29 Functions. It is intentionally structured so the research can be expanded to:

- L2 Sub-function code;
- Activity code;
- Construction Job Profile ID(s);
- exact job task / user story;
- product module / command / workspace;
- input records;
- operation performed;
- work product / transaction / decision / evidence produced;
- file/data formats;
- lifecycle and status model;
- approval / authority model;
- collaboration and handoff model;
- audit/evidence model;
- canonical NuBlox object mapping;
- migration/import/export implications;
- NuBlox native requirement;
- NuBlox coverage state;
- evidence URL and verification date.

## Product direction test

The research is complete enough to drive product design only when NuBlox can answer, for every supported Job Profile:

> What tools does this person use today to perform every material task of the job, and what native NuBlox capability replaces or improves that work without losing its professional output, control semantics or evidence?

A document repository is not a CAD/BIM authoring tool.  
A workflow engine is not an estimating system.  
A project record is not a construction programme.  
A file upload is not controlled technical information.  
An asset register is not a maintenance operating system.

NuBlox must benchmark the **operative work**, not merely the surrounding record.

## Current external evidence anchors

Current vendor material confirms the breadth and overlap that the register must decompose:

- SAP currently positions Cloud ERP across finance, supply chain and procurement, with adjacent products including Signavio, Ariba, field service, PLM, manufacturing, asset and sustainability capabilities.
- Oracle Fusion Cloud currently spans ERP, procurement, project management, risk/compliance, EPM, SCM, manufacturing, PLM, HCM, sales and service; Oracle Construction & Engineering separately includes Aconex, Primavera Cloud, P6, Unifier and Textura.
- Microsoft Dynamics 365 currently spans Sales, Customer Service, Field Service, Finance, Supply Chain Management, Project Operations and Human Resources.
- Diligent One spans board governance and GRC; OneTrust spans privacy, data-use governance, technology risk/compliance and third-party risk.
- PTC Windchill continues to provide BOM, engineering change and configuration management patterns.
- IBM Maximo and Planon cover significant physical-asset, maintenance, facilities and field-work domains.
- Nemetschek's current AEC portfolio includes ALLPLAN, Bluebeam, dRofus/dTwin, Graphisoft, Solibri, Spacewell and Vectorworks, demonstrating why professional tooling must be researched below ERP-suite level.

This is the evidence base for deciding what NuBlox actually has to build.
