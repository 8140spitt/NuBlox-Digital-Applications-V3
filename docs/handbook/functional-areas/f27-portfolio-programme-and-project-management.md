# F27 — Portfolio, Programme & Project Management

## Why this functional area exists

Select, authorise, plan, resource, execute, control and close portfolios, programmes and projects so that the enterprise delivers agreed outcomes predictably.

NuBlox must allow the people responsible for this function to carry out the complete function without relying on disconnected departmental spreadsheets or applications for its core enterprise work.

## What the function is responsible for

- manage initiative/project portfolio;
- evaluate investment/business cases;
- define/manage programmes;
- initiate projects;
- plan scope/WBS/schedule/resources/budget;
- control risk/issues/actions/decisions;
- manage project change;
- monitor progress/status/forecast;
- provide PMO methods/templates/assurance;
- manage portfolio resource demand/allocation;

## Typical people who work in this function

- Portfolio Director / Manager;
- Programme Director / Manager;
- Project Director / Manager;
- Project Planner;
- Project Controls Manager;
- PMO Manager / Analyst;
- Project Coordinator;
- Resource Manager;

Job titles vary by organisation. The functional area describes the business responsibility; Job Profiles and Positions describe who performs it.

## Core business processes

- Portfolio selection/prioritisation;
- Investment approval;
- Programme management;
- Project initiation;
- Project planning;
- Project execution/control;
- Project change;
- Project reporting/forecast;
- Closure/handover;
- PMO governance;
- Portfolio resource management;

## What people do day to day

- update plans/schedules;
- coordinate teams/actions;
- manage risks/issues/decisions;
- review progress/cost/forecast;
- raise/assess changes;
- prepare status/governance packs;
- manage dependencies/resources;
- close/hand over work;

## Core information and data

- portfolios;
- programmes;
- projects;
- stages;
- WBS/work packages;
- milestones/schedules;
- resources;
- budgets/forecasts;
- risks/issues/actions/decisions;
- changes;
- status/benefits;

The function consumes shared enterprise data and contributes new governed business state. It must not create private copies of canonical customers, suppliers, projects, people, contracts, assets or other shared objects.

## Key transactions, records and outputs

- portfolio register;
- business case;
- programme charter;
- project charter;
- project management plan;
- WBS;
- schedule;
- budget/resource plan;
- risk/issue/action/decision register;
- change record;
- status/forecast report;
- closure/handover pack;

These may be structured records, calculations, controlled information, transactions, decisions, inspections, reports or handover packages. NuBlox must support the appropriate form rather than forcing every output into a document.

## Decisions and controls

- portfolio priority/investment;
- project/programme initiation;
- baseline approval;
- change approval;
- exception/escalation;
- stage/gate decision;
- project closure/acceptance;

Authority must be enforced independently from job title. Assignment to work does not itself grant approval, financial, contractual or access authority.

## Performance measures

Typical measures include:

- portfolio value;
- milestone/schedule performance;
- cost/forecast variance;
- change exposure;
- risk/issue ageing;
- resource utilisation;
- delivery confidence;
- benefit/outcome attainment;

Measures are configurable by tenant and should drill back to the underlying governed data.

## How this function interacts with the rest of the business

- all delivery/corporate functions participate;
- F01 Strategy for initiatives;
- F14 Finance for funding/accounting;
- F07 Commercial for client commitments;
- F09 Procurement;
- F13/F23 assurance;
- F22 Asset handover;

The handoffs use shared canonical objects and governed workflows rather than point-to-point copies between departmental systems.

## What NuBlox must provide

For this functional area to be genuinely operable inside NuBlox, the product must provide:

- portfolio/programme/project hierarchy;
- business case/investment gate;
- WBS and structures;
- integrated schedule/baseline/progress;
- resource planning;
- risk/issue/action/decision/change;
- status/forecast governance;
- PMO standards/assurance;
- closeout/handover;

## Product-completeness test

This function is not complete because a menu item or dashboard exists.

It is complete when authorised people in this functional area can execute their normal end-to-end responsibilities in NuBlox, including the exceptions, approvals, evidence, handoffs and reporting required by a sophisticated construction and built-environment business.
