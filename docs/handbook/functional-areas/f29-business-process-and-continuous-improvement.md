# F29 — Business Process & Continuous Improvement

## Why this functional area exists

Define how enterprise work should flow, make processes visible and controlled, remove waste, automate where appropriate and continuously improve performance.

NuBlox must allow the people responsible for this function to carry out the complete function without relying on disconnected departmental spreadsheets or applications for its core enterprise work.

## What the function is responsible for

- maintain enterprise process architecture and catalogue;
- assign process ownership/accountability;
- discover/model current-state processes;
- analyse process performance and handoffs;
- design future-state processes;
- standardise procedures/SOPs;
- identify and implement workflow/automation;
- manage continuous improvement;
- monitor process compliance/deviation;
- define and analyse process KPIs;

## Typical people who work in this function

- Business Process Director / Manager;
- Business Process Analyst;
- Process Architect;
- Continuous Improvement Manager / Specialist;
- Lean / Operational Excellence Specialist;
- Workflow / Automation Analyst;
- Process Owner;

Job titles vary by organisation. The functional area describes the business responsibility; Job Profiles and Positions describe who performs it.

## Core business processes

- Process architecture;
- Process governance;
- Process discovery/modelling;
- Process analysis;
- Future-state redesign;
- SOP standardisation;
- Workflow automation;
- Continuous improvement;
- Process compliance;
- Process performance management;

## What people do day to day

- model processes/SIPOCs;
- interview users and capture work;
- analyse cycle time/bottlenecks/handoffs;
- design improved flows;
- write/update SOPs;
- configure/test workflows;
- track deviations and process KPIs;
- run improvement initiatives;

## Core information and data

- process hierarchy;
- processes/activities;
- owners;
- inputs/outputs/controls;
- handoffs;
- cycle times;
- SOPs;
- workflow definitions;
- automation rules;
- deviations;
- process KPIs;

The function consumes shared enterprise data and contributes new governed business state. It must not create private copies of canonical customers, suppliers, projects, people, contracts, assets or other shared objects.

## Key transactions, records and outputs

- process architecture/catalogue;
- ownership/RACI;
- current-state model;
- SIPOC;
- performance baseline;
- bottleneck assessment;
- future-state model;
- SOP;
- automation definition/test/deployment;
- process deviation/corrective action;
- process KPI report;

These may be structured records, calculations, controlled information, transactions, decisions, inspections, reports or handover packages. NuBlox must support the appropriate form rather than forcing every output into a document.

## Decisions and controls

- process ownership;
- future-state approval;
- SOP approval;
- automation release;
- process exception;
- improvement prioritisation;
- process/control change;

Authority must be enforced independently from job title. Assignment to work does not itself grant approval, financial, contractual or access authority.

## Performance measures

Typical measures include:

- cycle time;
- touch time;
- handoff delay;
- rework;
- process compliance;
- automation rate;
- defect/waste reduction;
- improvement benefits;
- SOP currency;

Measures are configurable by tenant and should drill back to the underlying governed data.

## How this function interacts with the rest of the business

- all functions are process participants/owners;
- F28 Transformation for enterprise change;
- F13 Quality for continuous improvement;
- F16 IT for automation platforms;
- F03 Performance for KPI;
- F26 Knowledge/Records for controlled SOPs;

The handoffs use shared canonical objects and governed workflows rather than point-to-point copies between departmental systems.

## What NuBlox must provide

For this functional area to be genuinely operable inside NuBlox, the product must provide:

- enterprise process architecture;
- process modelling/SIPOC;
- ownership/governance;
- performance and bottleneck analysis;
- future-state design;
- controlled SOP lifecycle;
- workflow/automation definition and testing;
- deviation/compliance cases;
- continuous-improvement portfolio and benefit tracking;

## Product-completeness test

This function is not complete because a menu item or dashboard exists.

It is complete when authorised people in this functional area can execute their normal end-to-end responsibilities in NuBlox, including the exceptions, approvals, evidence, handoffs and reporting required by a sophisticated construction and built-environment business.
