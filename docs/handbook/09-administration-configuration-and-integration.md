# 09 — Administration, Configuration & Integration

## Administration model

NuBlox administration has three distinct areas.

### Enterprise setup

Defines the organisation being operated: legal entities, enterprise groups, organisation structure, people/worker relationships, positions/jobs, sites/properties, products/services/items, projects/contracts, assets and customer/supplier relationships.

### Business configuration

Defines how the enterprise wants NuBlox to behave: numbering schemes, classifications, lifecycles, workflows, approval rules, authority rules, status/suitability codes, calendars, currencies, units, templates, document/deliverable types, retention rules and reference data.

### Technical administration

Operates the platform: authentication, identity connection, tenant membership, integrations, queues/outbox, environment diagnostics, database migrations and technical health.

## Security administration

Administrators manage role definitions, permissions, assignments, scopes, delegated authority, approval authority, access requests and periodic review/certification where required.

## Deliverable configuration

Administrators and business owners should be able to govern deliverable types, numbering patterns, disciplines, metadata, lifecycle/status, revision rules, suitability/status codes, review/approval routes, issue/transmittal rules, templates, retention and connected-authoring behaviour.

## Integration

NuBlox must interoperate with specialist systems where specialist authoring or external business networks remain appropriate.

Integration patterns may include APIs, webhooks/business events, file/model exchange, scheduled import/export, connectors/adapters, external identifiers and deep links.

Potential connected categories include CAD/BIM/design tools, scheduling/planning tools, estimating applications, banking/tax services, payroll/benefits, identity providers, document/model viewers, GIS, IoT/building telemetry and supplier/customer networks.

## Integration rule

An external application may author specialist content, but NuBlox retains its enterprise meaning, responsibility, context, lifecycle, evidence and handoff where NuBlox is the governing enterprise system.

## Import and migration

Enterprise implementation requires controlled import/migration for parties/organisations, people/jobs/positions, products/items, suppliers/customers, projects/contracts, assets, classifications/reference data, existing documents/deliverables and open transactions.

Migration must preserve provenance and must not silently create duplicate identities.
